## Uçtan uca (e2e)

Uçtan uca (canlı Supabase'e karşı; test kullanıcıları/grupları oluşturur ve **sonunda siler**):
**Yerel (Windows):** Playwright geliştirme bağımlılığı (`npm install` ile gelir); tarayıcı bir kez indirilir: `npx playwright install chromium`.
`npm run dev` açıkken (localhost:3000) tek senaryo: `node scripts/e2e/nav.mjs`. `npm install` sonrası açık dev sunucusu bozulabilir
("Jest worker encountered … child process exceptions") → sunucuyu yeniden başlat.
**Tuzak:** dev sunucusu açıkken `npm run build` çalıştırma; `.next`in üzerine yazar, sunucu JS dosyalarını 404 verir, sayfa canlanmaz (giriş formu `/login?` diye GET olur, e2e girişte takılır) → sunucuyu yeniden başlat.
```bash
node scripts/e2e/nav.mjs
```
**Dev sunucusu tuhaflığı (üretimde yok)**: `npm run dev`de kendisi yönlendiren sayfaya istemci geçişi (girişten sonra `/` → `/hosgeldin`, karşılamadan sonra `/join/…` → `/g/…`) boş sayfada kalabiliyor; canlıda doğru çalışıyor. Bu yüzden `auth-onboarding` takılırsa bir kez yeniler (`settle`). Menü/davet testlerinde çekmece içeriği `waitFor` ile beklenir.
`notifications` ve `cron-tick` cron adımları sunucunun .env.local içindeki `CRON_SECRET`ini kullanır; yoksa o adım "ATLANDI" yazar.
Senaryolar: `match-manage` (4b: Keşfet ilanı + yabancı başvurusu/onayı, başka gruba onaylı ilan, `/davet/m/<kod>` ile başvuru, dolu kadroda yedek ve yedekten alma, rakip adı, kesinleştir, ertele, iptal, teklif + karşı teklif + kabul), `match-setup` (Maç ayarla sihirbazı: adımlar, telefon geri tuşu, saha ücreti, takım dışı arkadaş, uygulamadaki rakibe teklif, Meydan Oku, gelenler + misafir + duyuru, toplanan maç, Geliyorum/yedek, Kadro tamam bildirimi, Gelemem ile çıkış, grup/ana sayfa listesi, direkt kesin maç, yetkisiz erişim, `?grup=` olmadan ana sayfaya), `join-requests` (6a/6b: Grubu yönet Keşfet/istek ayarı, Keşfet Gruplar sekmesinden istek (geri al, notla tekrar), kaptana bildirim, takım sayfasından istek (kapalı/açık), istek → ana sayfa yapılacaklar, grup sayfası "Bekleyen istekler", /istekler kabul/ret, bildirimler, red sonrası tekrar istek yok, üye sayfaya giremez, İstekler sayfası Realtime ile yenilenir), `proposals-teams` (öneri → istekler sayfasında onay, format → öneren adına toplanan maç → üyeler Geliyorum → öneren kesinleştirir, taraflar bölünür; sessize alma), ödünç davet, sessize alma), `nav` (geri oku), `profile-links`, `invite`, `withdrawal`, `leave`, `menu`, `profile`, `skills`, `positions-external`, `auth-onboarding`, `teams` (takım kurma, roller, görünürlük, Keşfet), `voting` (oylama ekranı: sekmeler, zorunlu puan, cihazda taslak, maç özeti, sonuç ekranı, takım puan tablosu + ▲▼, istatistik sayfası), `match-card` (Maça çağır: arkadaşa/aramayla yabancıya kart = kişiye özel davet, gizli profil aramada yok, sohbette canlı kart (sayaç, Davetlisin/Kadrodasın), davetli maça bakıp Geliyorum (ödünç), ana sayfadan hızlı Geliyorum, Keşfet Adam arayan il süzgeci + başvuru), `regions-community` (il/ilçe, grup kurma, Grubu yönet'te grup bilgilerini düzenleme), `chat`, `challenges` (ana sayfada teklif ve yaklaşan maç kartı dahil), `guest-match`, `cron-tick` (zamanlanmış işler, sonuçsuz kapanış bildirimi dahil; sunucu .env.local CRON_SECRET ile), `realtime`, `notifications`, `card-photo` (kırpma + arka plan kaldırma), `discover` (Keşfet oyuncu araması süzgeçleri, aramada görün ayarı, öne çıkanlar: bölge çipleri, sekmeler), `dm` (istek akışı, canlı mesajlaşma, gelen kutusu), `dm-invite` (profilden takıma davet, sohbette kabul, davet kartlı grubu silme), `friends` (istek, Sosyal'de kabul, arkadaşlar arası doğrudan sohbet), `inbox` (sohbet listesi arama/süzgeç, mesaj kısayolları), `settings` (Ayarlar ana/alt ekranlar, müsaitlik, istatistik paylaşımı, dondurma, engelleme, geri bildirim).
**Temizlik kuralı**: her senaryo `finally` içinde `removeTestUsers(admin, ids)` (`scripts/e2e/cleanup.mjs`) çağırır: test kullanıcılarının kurduğu/üye olduğu gruplar (başka hesaplı üyesi yoksa), teklifler ve kullanıcılar silinir; eksik kalırsa `⚠ TEMİZLİK EKSİK` yazar. Yeni senaryoda `deleteUser`'ı doğrudan çağırma (grup/maç `created_by` kullanıcıyı tutar, silme sessizce başarısız olur). Test kullanıcıları `@example.com`; kontrol: canlıda bu alan adıyla kullanıcı kalmamalı.
Kullanıcıyı API ile kuran senaryo karşılamayı atlamak için `profiles.onboarded_at` (+ il) doldurur; yoksa her sayfa `/hosgeldin`'e yönlenir.
Ekran görüntülerine bak (390px genişlik, telefon) — görsel sorunlar çoğu zaman sadece orada yakalanıyor.
Port doluysa: `fuser -k 3000/tcp`. Arayüzden kayıt (signUp) sadece e-posta onayı kapalıyken test edilir (`auth-onboarding`); onay açılırsa mail gönderir (limit saatte 2), o bölüm kaldırılmalı.
